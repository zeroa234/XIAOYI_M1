# 独立参考解码：候选分析输入

复用现成的 `cebix/ff7tools` LZSS 实现，未修改源文件，也未自写压缩/解压算法。其参数为 4096 字节窗口、3–18 字节引用及 4078 初始位置，与当前候选格式吻合；这仍不能单独证明 M1 解码兼容性。作者许可保留在源文件头。

来源固定为提交 `6bf1fbcec2c88c1856cffd4a371719b406fee654`，文件 SHA-256 为 `ee3b65e055231164d29ac53a67da1dd047c2e761b932c6a3efb27e6d7f102f84`，详见 `reference-codec-source.json`。代码仅安装在项目 `vendor/ff7tools-reference/lzss.py`。

自写部分是 `scripts/reference-decode.py`：核对输入哈希、读取原始装载/节表、调用参考库、保存全量结果与表长限定视图，并明确记录尾部。脚本没有设备接口或重打包功能。

本轮通过 3 个参考解码向量、5 个小样本压缩/解压完整往返。它们测试参考实现的预期语义，不是相机兼容性测试。

## 原厂表长核对

压缩负载长度直接读取原始未压缩装载表中的 `.ROM.text/.ROM.rodata/.ROM.data`，不再使用零填充启发式。映射长度读取 `.text/.rodata/.data`。名称必须精确匹配，避免把 `.data` 匹配到 `.ROM.data` 内部。

| 版本/节 | 压缩长度 | 表中映射长度 | 参考解码长度 | 额外输出 |
| --- | ---: | ---: | ---: | --- |
| 3.2 .text | 3,117,324 | 4,445,240 | 4,445,241 | `ff`，1 字节 |
| 3.2 .rodata | 4,124,532 | 5,703,192 | 5,703,192 | 无 |
| 3.2 .data | 116,761 | 339,536 | 339,537 | `ff`，1 字节 |
| 3.1 .text | 3,117,559 | 4,445,200 | 4,445,200 | 无 |
| 3.1 .rodata | 4,124,550 | 5,703,196 | 5,703,197 | `ff`，1 字节 |
| 3.1 .data | 116,784 | 339,536 | 339,537 | `ff`，1 字节 |

完整输出存为 `output/reference-decoded/body-*/<section>.full.candidate.bin`。按表长取出的静态分析视图另存为 `<section>.mapped.candidate.bin`。原始候选输出未被覆盖或静默裁剪；额外输出长度、内容前缀及哈希均在 `reference-decode-results.json` 中。`ff` 的机身格式含义尚未验证。

此结果提供更有依据的静态分析输入，但未验证实际机身解码器，也没有生成相机更新文件。主程序函数/地址仍需反汇编与行为证据交叉确认。

## 复现

在源码已按来源清单放置的条件下，从项目目录运行：

```powershell
python -B scripts/reference-decode.py
```

脚本保持官方输入和原工具产物不变，只重建候选输出及对应报告；终端仅输出六条摘要。临时的早期探索输出不作为核实结论。
