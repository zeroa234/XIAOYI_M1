# 3.2-cn 可修改部分与功能扩展的可行性

日期：2026-10-26。用户询问除挂死/曝光预览外还有哪些优化或新功能。目标仍为保留 3.2-cn 功能。本文是功能范围评估，不表示这些机身补丁已经完成。

## 现成方案与证据

优先复用现成实现：

- [bullbin/xiaoyi_m1_re_liveview](https://github.com/bullbin/xiaoyi_m1_re_liveview)：BLE/Wi-Fi 配对、控制和取景协议的现有实现，作者限定实测版本 3.2-int。
- [echeetah/yi-m1-monitor](https://github.com/echeetah/yi-m1-monitor)：现有 macOS/iOS 监看和遥控应用，包含远程调参、拍照/录像、峰值和构图辅助。作者同样只在 3.2-int 实测，不能直接推广到用户的 CN 版本或 Windows。
- 本项目已有 Capstone/Ghidra/Unicorn 分析链，远程命令越界已通过候选机器码隔离执行；不需另写 CPU 模拟或解压算法。本轮没有新写算法、工具或相机程序。

## 可行性分层

| 项目 | 已掌握的证据 | 当前可承诺的范围 / 仍缺什么 |
| --- | --- | --- |
| 远程命令搜索越界修正 | 本地候选 ARM 指令与 106 个隔离用例 | 有具体的局部修改方案；解码/重打包/实机验证仍未完成，也未与日常卡死关联 |
| 扩展录像格式 | 现有项目报告实测 FHD_24、720P_24/30/60、VGA_240；CN 候选也有对应值 | 值得优先验证 CN 的实际录像文件；加入机身菜单还需找 UI 枚举、参数映射与校验，不是加一行文字就完成 |
| 自定义参数组、照片/视频快捷预设 | 已有协议能调多种曝光和拍摄参数 | 外部遥控工具可在已有接口上设计；机身本地保存/调用需定位持久化和切换路径。用户此前的“普遍不记忆”已撤回，不作为已确认缺陷 |
| 快捷菜单、按键/长按功能调整 | 目前只有一般 UI/设置路径线索 | 适合作为独立逆向目标；尚未识别可直接修改的具体事件表和完整状态约束，不能承诺已经能改 |
| 间隔拍摄、自动曝光序列 | 现有调参、触发拍摄接口可以作为构件 | 外部工具可设计串行调参、确认状态、触发的流程；精确时序、拍摄完成确认和本机兼容待验证。机身离线运行版本需要新增状态机、定时和取消/错误处理路径 |
| 峰值阈值/颜色、斑马纹、波形等辅助 | 已有外部监看程序实现峰值；机身已有 MF+PF 相关线索 | 外部取景可扩展显示辅助；机身显示缓冲、叠加层、算力和刷新流程未定位。不能把外部显示辅助当成机身更新，也不能把处理后的预览亮度当成真实曝光模拟 |
| UI 响应、镜头通信等待优化 | 用户观察明确，但无时序/任务栈 | 重复刷新、同步等待或超时是调查候选，不是已定位缺陷。需要找到真实等待点和状态约束，不能任意删等待或提升时钟 |
| 真实曝光模拟、AF 算法改进 | 已有设置、成像状态线索 | 仍属底层工作；曝光须区分传感器曝光与取景增益，AF 须定位搜索/镜头控制与时序。暂不能承诺成果 |

无缝长录、RAW 视频、4K60、10-bit 或任意码率，不列为已确认可添加的功能。相关能力涉及硬件、子处理器、缓存及文件写入约束，现有主固件字符串和接口不足以证明支持或绝对不支持。

## 录像模式线索的独立核查

来源：[录像格式命令与文件验证](https://github.com/echeetah/yi-m1-monitor/blob/main/fable%20research/rcvideoformatset-solved.md)、[隐藏值实测记录](https://github.com/echeetah/yi-m1-monitor/blob/main/fable%20research/hidden-value-candidates.md)。这是作者自己报告的 3.2-int 实测，不是本项目实机验证。

作者列出 FHD_24 的文件为 1920×1080、24000/1001 fps，并用 FHD_30 文件作对照；VGA_240 被报告为 640×480、约 240 fps 采集并保存为 30 fps 慢动作文件。720P_24/30/60 亦列为有效模式。其早期记录对 4K_24 的“成功”后来被撤回：仅 HTTP 200 不代表格式实际生效，因此不推荐声称已解锁 4K24。

2026-10-26 本地只读复核：先核对 .rodata 候选 SHA-256 与固定报告一致，再找到以下 NUL 结尾字符串：

| 内容 | CN 候选文件偏移 | 候选虚拟地址 |
| --- | --- | --- |
| RCVideoFormatSet | 0x278e68 | 0x6b8668 |
| Resolution | 0x278c12 | 0x6b8412 |
| FHD_24 | 0x2794fa | 0x6b8cfa |
| 720P_60 | 0x2790ac | 0x6b88ac |
| 720P_30 | 0x2790b4 | 0x6b88b4 |
| 720P_24 | 0x2790bc | 0x6b88bc |
| VGA_240 | 0x2790c4 | 0x6b88c4 |
| MF-PEAK | 0x27901c | 0x6b881c |

这些只是候选字节证据，不证明对应模式在 CN 机身有效，也不证明加入菜单所需改动已知。没有向相机发送模式设置命令，没有连接相机 Wi-Fi，没有安装新的遥控应用。

## 建议范围

机身研发先集中在已定位的局部缺陷、现有录像模式到 UI 的映射、自定义参数组/快捷操作三个可单独评审的目标；每项仍需验证。曝光预览与完全挂死保持原有优先级和调查状态，不能用新增功能的完成替代修复。

如果需要尽快获得拍摄辅助，可复用现有遥控/监看项目作为另一条路线；这是外部软件选择，不代替用户要求的机身固件。
