# 不拆机软件调查：属性路径与错误分支

日期：2026-10-26。用户明确选择只做不拆机软件调查。保留 3.2-cn 功能、定位完全挂死/卡顿及实现曝光模拟的目标不变。所有固件地址均来自尚未经真机内存验证的标准语义候选，不是可直接刷写的补丁位置。

## 1. 曝光设置路径取得的进展

从真实 HTTP 命令表获取处理函数，而不是推测相邻地址：ISO `0x155a10`、快门 `0x155940`、光圈 `0x155894`、EV `0x1559a8`。其输出的内部动作号分别为 `0x1d/0x1b/0x1a/0x1c`；`0x1623f4` 用动作号减 `0x13`，从 `0x833040` 的23项函数表分派。逐条指令确认下列内部属性号：

| 设置 | 内部属性号 | 分派入口 |
| --- | ---: | --- |
| ISO | 5 | 0x1629b4 → 0x162878 |
| 快门 | 0x13 | 0x1629a4 → 0x162878 |
| EV | 0x12 | 0x1629ac → 0x162878 |
| 光圈 | 0x14 | 0x162988 |

这些路径到达 `0x15db34`，先调用 `0x15a7e0`，再转到 `0x15c5bc`。后两个函数中的间接跳转未被 Ghidra 恢复，因此复用现有 Unicorn 执行它们的真实 CPU 指令，**在跳入具体处理块之前停止**，没有模拟外设或执行属性处理程序。四个属性、每个三个入口数值、两个分派器，共24个隔离用例得到一致的目标：

| 设置 | 第一分派块 | 第二分派块 | 后续包装/候选回调 |
| --- | --- | --- | --- |
| ISO | 0x15a840 | 0x15c670 | 0x420c8 / 0x44338 |
| 快门 | 0x15abe0 | 0x15c920 | 0x43198 / 0x45efc |
| EV | 0x15abcc | 0x15c77c | 0x42db4 / 0x455f0 |
| 光圈 | 0x15ac10 | 0x15c6b4 | 0x432cc / 0x46008 |

第一/第二分派是分析标签，不能据名字认定已经设置传感器。后续包装传入12字节结构及回调地址到 `0x26c8c`；该函数构造编号0x15的结构，经 `0x126d9c` 传递。这补足了设置到内部消息路径的静态证据，尚未连通到真实取景曝光、增益或显示补偿。

工具：`scripts/resolve-exposure-dispatch.py`；结果：`exposure-dispatch-results.json`；指令块摘要：`logs/exposure-dispatch-blocks.txt`。`config/exposure-dispatch-targets.txt` 是分支块地址，**不是函数入口列表**。

## 2. 与完全挂死有关的新线索

在上述内部消息路径中，`0x126d9c` 调用 `0x199874` 后，到达错误处理尾部：

- 返回0时，`0x126ed4` 的共享助手直接恢复父函数栈并返回。
- 返回-43时，尾部转换为2并返回。
- 其他未处理返回值继续到 `0x126df8: b 0x126df8`，即无条件原地循环。

这类共享助手会直接返回到父调用者，普通 C 反编译不能完整表达；不能把生成的 C 中无意义循环当作程序缺陷。上述错误尾部则已由真实指令和隔离执行交叉核查：输入0、-43正常返回；输入-18、-42、-17分别连续访问原地分支8次而没有返回。状态值和保存的返回栈由测试装置提供，没有执行整个内核或消息队列。

工具：`scripts/check-message-error-path.py`；结果：`message-error-path-results.json`，5个用例通过。3.1候选的 `0x126db0` 有完全相同的20字节尾部，因此不是已证明的3.2新增缺陷。

**已证明的范围：候选机器码存在特定错误导致当前执行路径自旋的机制。尚未证明用户的相机触发这些返回值、哪个任务/核心会进入此处，或这解释了整机完全挂死。** 不删除该分支、不吞掉错误、不把它作为已完成的稳定性修复。下一步应查上游对象/参数有效性与对象生命周期，以及能否通过已确认的软件输出记录实际错误。

只读 PnP 查询仍看到 `YI YI-M1 USB Device` 的 DiskDrive。蓝牙适配器名称过滤没有命中，不能据此断言电脑没有蓝牙硬件。已询问用户可用的配对设备，以确定后续连接方式；没有访问SD、切换网络或发相机命令。

真正采集前要明确目标相机、配对方式、PC连接方法和采集范围。Wi-Fi遥控会改变工作模式，不当作本地触屏操作完全等价的性能测试；不通过反复调参制造挂死。
