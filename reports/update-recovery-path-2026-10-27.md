# SD 升级器、NAND 分区与启动回退路径

日期：2026-10-27。只读离线定位：Pi 子代理 `pa-f0fd7959` 负责查找，主代理逐条核对指令；未生成固件、未操作相机。输入为顺序复制语义的 3.2-cn 候选（`.text@0x2000`、`.rodata@0x43f800`）与未压缩 IPL。标注：【主核】= 主代理用 Capstone 亲自核对指令；【子核】= 子代理给出指令、主代理未逐条重看；【推断】= 由已核事实推出。

## 结论

1. 官方升级器在主程序里，按头中 `SUM=` 对每段做字节累加校验，检查设备号 `C59Y1`；**没有找到禁止降级的版本数值比较**。
2. 升级包里出现哪些段就写哪些段：主程序、ND1、ND2、IPL、PTBL。官方包含 `ND1 IPL PTBL`，因此**每次官方升级都会重写 IPL 和 PTBL**。
3. NAND 上另有一个 **BOOT 分区**，升级器的分派里没有它，官方包也不含它，所以官方升级从不写 BOOT【推断】。
4. IPL 平时启动 FIRM。**FIRM 加载失败时自动改载 BOOT**；开机时若"开机原因"寄存器和一组输入位满足特定模式，也会直接启动 BOOT。**IPL 没有从 SD 或 USB 加载的分支。**
5. BOOT 里是什么程序、对应哪几个物理按键，目前都未知；BOOT 内容不在任何官方包里，离线读不到。

所以若将来修改主程序：只要改动后的程序还能进入 UI，就能用官方 SD 升级刷回原版；若加载阶段失败会落到 BOOT（行为未知）；若加载成功但在 UI 之前崩溃，目前**没有已知的恢复办法**。

## 1. 头解析与校验【主核】

`0x10f954` 起解析 0x100 字节头：

```
0010f9b8 ldr r1,[pc,#0x228]   ; ="LENGTH="
0010f9d8 bl  0x190c7c          ; sscanf "%ld" -> [r5+4]
0010f9dc ldr r1,[pc,#0x20c]   ; ="SUM="
0010f9fc bl  0x190c7c          ; -> [sp+4]
0010fa04 add r0,r4,#0x100      ; 段体起点
0010fa14 subs fp,fp,#1 / ldrbhs r3,[r0],#1 / addhs sl,r3,sl / bhs   ; 逐字节累加 LENGTH 字节
0010fa28 cmp sl,r0 / bne 0x10fb98                                   ; 与 SUM 不等则失败
0010fa3c ldr r1,[pc,#0x1b0]   ; ="LOADADDRESS="（可选）
```

与 `container-and-decode-check.json` 的离线结果一致。【子核】`0x1102c0` 要求以 `LENGTH=` 开头，`0x1102d4` 要求 `C59Y1` 出现在前 0x40 字节内，`VER=` 只限长度（≤10 字符）。

入口【子核】：`0x10fe64` 是执行体，有 5 个调用点；UI 菜单路径 `0x208ac`（mode 0，之前 `0x2076c cmp r0,#0x32` 检查电量 ≥50%）。`0x10be80` 以 mode 1 调用、先读 RAM 标志 `0xc14ca473`，像是开机时检查待升级标志，标志写入者未找到。

## 2. 各段写到哪里【主核】

`0x10f6bc` 按段号分派：

| 段号 | 段 | 处理 | 位置（512 字节扇区） |
| --- | --- | --- | --- |
| 0 | 主程序（首段，无名） | `0x10f744` | 写在 `0xb000 − 向上取整到 128 KB 的长度` 处，即紧贴 ND1 之前 |
| 1 | ND1 | `0x10f6fc` | 从 0xb000 扇区起，上限 0x7700 扇区 |
| 3 | ND2 | `0x10f774` | 0x6e00 起，上限 0xb800 |
| 5 | IPL | `0x10f7c4` | 经 `0x10f324(0x64)` 等 |
| 10 | PTBL | `0x10f790` | 经 `0x1104a4(…,0x2083/0x2082)` |

0xb000 × 512 = 0x1600000，正好是 ND1 头的 `OFFSET=23068672`，由此确定这些计数以 512 字节为单位。名字表在 `.rodata 0x54c23c`：`PTBL NPROG/NPG NDATA/ND1 NLIPI/NPI NDAT2/ND2 IPL`。分派中只有段号 0/1/3/5/10，**没有 BOOT**。写后是否回读校验未确认。

## 3. PTBL 分区表【主核】

格式：`"@PEI"`、版本 1、条目数 13，每条 6 个字 `{id, ?, ?, 装载地址, 起始, 长度}`。id→名字表在 IPL 文件 0x111d0，17 个名字指针全部按 `VA = 文件偏移 + 0x22ffc000` 解析成功，这也说明 IPL 数据在运行期映射到 0x22ffc000 起。

| 分区 | id | 起始 | 长度 | 装载地址 |
| --- | --- | ---: | ---: | --- |
| BOOT | 0x10000010 | 0x200 | 0x400 | — |
| USER | 0x10000021 | 0x600 | 0x1000 | 0xc1e00000 |
| DEBUG | 0x10000022 | 0x1600 | 0x5000 | — |
| ARM926_1 / ARM926_2 / ARM9 | 0x10000101–103 | 0x6600 / 0x7600 / 0x8600 | 各 0x1000 | — |
| DATA0–3 | 0x10000200–203 | 0x9600 / 0xe600 / 0xee00 / 0xf600 | 0x5000 / 0x800×3 | 0xc2000000 / c2a00000 / c2b00000 / c2c00000 |
| CAMDEF | 0x10000013 | 0xfe00 | 0x200 | 0xdffe0000 |
| CAMADJ | 0x10000011 | 0x10000 | 0x200 | 0xdffa0000 |
| FIRM | 0x10000012 | 0x10200 | 0x23600 | — |

名字表里有 `FIRM2`（0x10000110）、`PART_TBL`、`STORAGE`，但 PTBL 没有这些条目，所以**不存在第二份主程序**。PTBL 的起始/长度单位尚未确定（与上节的升级器扇区计数分属不同的地址层，未对齐）。

## 4. IPL 启动选择与回退【主核】

```
004144 bl 0x7834              ; 选择分区 id
004158 bl 0x7ff8              ; LoadData(…, id, …)
00415c cmp r0,#0 / beq 0x419c
004164 ldr ip,=0x10000012 / cmp r7,ip / bne   ; 失败且是 FIRM
004170 ldr r0,=0x2300cb24     ; "Instead, I'll load BOOT for you."
004178 ldr r7,=0x10000010     ; 改载 BOOT
004188 bl 0x7ff8
0041a8 bl 0x6740 / cmp r0,#0 / beq   ; 建段描述符
0041b4 ldr r0,=0x2300cb48     ; "Invalid Firmware?"，返回 6
```

`0x7834` 的选择条件：

1. 轮询 `0x22000300` 一带的寄存器最多 0x80000 次，超时打印 `PSQ PWR Factor Wait Skip`（0x2300cfd8）。
2. `0x7588` 仅在 `[0x22000308]==0` 且 `([0x2200030c] & ~0x80000) == 0x100000` 时返回 1。
3. 之后 `0x75c0` 配置 `0x22000000 |= 0x300` 并按位扫描 mask 0x1e 的输入，延时后判断 `([0x22000314] & 0x1e) == 0xa` 且 `([0x22000310] & 1) == 0`。
4. 两个条件都满足才返回 BOOT（`0x7904`），否则返回 FIRM（`0x790c`）。

【推断】PSQ 是电源时序器，`0x2200030c` 记录开机原因，`0x22000314` 的位是按键或引脚输入。合起来像"以特定方式开机并同时按住某组按键"进入 BOOT。具体哪几个物理按键、BOOT 做什么，未知。

## 5. 升级器只写包头里列出的命名段【主核】

固定表 `.rodata 0x54c1ec` 有 10 项 `{名字, 段号}`：PTBL→10、NPROG/NPG→0、NDATA/ND1→1、NLIPI/NPI→2、NDAT2/ND2→3、IPL→5。

```
0010fa7c ldr r1,=0x54c1ec / ldr r1,[r1,fp,lsl#3]   ; 第 fp 个名字
0010fa8c bl  0x110420                               ; 在 0x100 字节头里查找
0010fa90 beq 0x10fb88                               ; 查不到：该项长度保持 0
0010fb88 add fp,fp,#1 / cmp fp,#0xa / blo 0x10fa7c
...
00110048 ldr r2,[r1,#0x24] / cmp r2,#0 / bls 0x110074   ; 长度为 0 则跳过
00110064 ldr r0,[0x54c1ec + i*8 + 4] / bl 0x10f6bc      ; 按段号写
```

因此包头不列 `IPL`、`PTBL` 时，这两段不会被写，写入顺序由固定表决定而与头内顺序无关。**首段主程序**（头里没有自己的名字）走哪条路径写入、写到 FIRM 的哪里，仍未定位。

## 5b. 首段主程序的写入与整体顺序【主核】

首段正文不走固定表里的 NPROG（段号 0）分支，而是在名字循环之后单独写入：

```
001100ac ldrb r0,[r5,#4]                 ; 来源类型（SD 路径由 0x110244 写入）
001100b4 moveq r0,#0x69 / 001100c0 moveq r0,#0x66 / 001100d0 mov r0,#0x64
001100d4 ldr r2,[r4] / 001100d8 ldr r1,[r4,#8]   ; LENGTH、对齐长度（r4 = 0x45545000 控制块）
001100dc bl 0x10f644                     ; 写首段正文
001100e0 cmp r0,#3 / beq 失败；cmp r0,#5 / bne 成功；=5 时报错码 0x171
0011010c bl 0x10fdd4                     ; 成功：设 RAM 标志后复位
```

因此写入顺序是 **PTBL → ND1 → IPL → 首段主程序（最后）**。【子核】写入层 `0x10f46c` 以 512 字节页、每批 12 页写出；**没有重试、回滚或写后回读校验**，失败即返回 -1；成功后不写任何 NAND 标志，设 RAM 标志并复位。中途断电可能留下"新 IPL/ND1 + 半写主程序"，能否恢复取决于 IPL 的 BOOT 回退。

**IPL 相同则跳过**【主核】：`0x10f7e8 bl 0x10f324` 逐页比较新旧 IPL，返回非 0（相同）时 `0x10f7f0 bne 0x10f808`，`movne r4,#1` 直接返回成功，不写；只有不同时才在 `0x10f7fc` 写入。子代理把这一分支读成"相同被判为错误"，不采纳。官方 3.1/3.2 的 IPL 逐字节相同，所以在这两版之间升级不会真正重写 IPL。

`0x10fd70`（在 `0x0115cc00`/`0x00d68400` 两个值之间切换的计数函数）没有静态调用者，**不能据此认为存在 A/B 双槽**。

## 6. 第二条升级通路【子核】

`0x1247b4` 一带处理命令 `0x0fedbebe`：子命令 0 重置 RAM 缓冲 `0x4554500c`，1 追加数据，2 置标志 `0xc14ca473=1`。`0x10be58` 读到该标志为 1 时以 mode 1 调用升级执行体 `0x10fe64`。这像是 App/无线传输固件的通路（`.rodata` 中 `\FIRMWARE.BIN`、`\LENS_FW.lin` 只被 App 文件接口 `0x154ac0` 引用）。命令发送方和标志的清除时机未找到。

## 7. 按键与开机原因【子核+推断】

- 主程序**不读** `0x22000308/0x2200030c/0x22000310`（全镜像字面量与线性扫描均无命中），这些寄存器只被 IPL 读。
- 主程序在 `0x2fca3c` 起读 `0x22000314` 的 bit2 并锁存，调用点之一是关机路径，推断 bit2 与电源键有关。
- 固件中没有按键名或事件码表，无法静态确定 bit1/bit3 是哪两个物理键。子代理推测"就是 Q+PLAYBACK"，**不采纳**：官方的 Q+PLAYBACK 是固件信息页里的 UI 组合键，与 IPL 开机时读取的输入位之间没有证据联系。
- `0x2200030c` 的 0x100000 表示哪种开机原因，没有枚举或字符串证据。

## 对今后改机身的约束

- 只要包头仍以 `LENGTH=` 开头、含 `C59Y1`、各段 SUM 正确，升级器就会接受；未见签名。
- 为了不碰引导程序，包头可以不列 IPL/PTBL（第 5 节已证这样会跳过它们）；但首段主程序的写入路径还没找到，在找到之前不能设计定制包。
- 修改只应放在进入 UI 之后才执行的代码里，并保留升级器路径不变，这样出问题时还能用官方 SD 升级刷回。
- BOOT 的行为和触发按键是恢复能力的最大未知；在弄清之前，不应把任何定制镜像交给用户刷写。

## 子代理结论中被纠正或未采纳的部分

- 子代理给出的 PTBL 条目名称顺序与本表一致；它称 PTBL 起始/长度"按字节解释矛盾"，这里改为"单位未定"。
- "0x10be80 是开机检测待升级"仍是推断，未采纳为结论。
