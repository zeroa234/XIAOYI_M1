# 曝光亮度模拟的标定方案

用户提出：对比真实照片与当时预览，再利用快门、ISO、光圈关系实现亮度预览。该方向可用于建立近似亮度模型；尚未实施照片采集或机身功能。

## 优先复用的现成方法

1. 相对曝光倍率：在同一光照、相同色彩处理且未饱和的近似线性响应下，取景基准(t0, S0, N0)到目标拍照参数(t, S, N)的显示信号倍率为 `g ≈ (t/t0) × (S/S0) × (N0/N)^2`。t是秒、S是ISO、N是f值；ISO表示信号增益关系，不表示增加到达传感器的光子数。等价档差为 `log2(g)`。
2. 相机响应标定：OpenCV现成 `createCalibrateDebevec` / `createCalibrateRobertson` 可从已知曝光时间的静止场景序列估计响应曲线。拍摄该序列应固定ISO、光圈、色彩、白平衡等；不同ISO的实际增益、取景流和最终照片的不同处理仍需单独验证，不能把三者不同的图片直接当成仅快门变化的输入。
3. 显示编码：使用已标定响应曲线，或在确知为sRGB时采用标准线性化/编码公式。JPEG数值不直接按曝光倍率相乘；本机取景曲线尚未测定，不能擅自当作严格sRGB/线性响应。

当前没有新增自写曝光算法。上述公式是标准相对曝光模型；今后若增加实现，应明确区分现成OpenCV标定、标准曲线转换和项目内的参数/机身接入适配。

## 必须取得的基准

菜单和UDP中的ISO/快门/光圈是设备报告的拍摄设置，尚不能替代取景传感器积分时间、实际光圈、模拟/数字增益及自动亮度补偿。一次照片与预览的标定可给出当时偏移；若取景自动增益随场景变化，固定偏移不能保证换场景后仍正确。

优先调查可读取/控制的真实取景AE状态或测光差值，再用固定灯光下的少量照片与预览配对检验模型。元数据EV字段的语义尚未证实，不直接把它代入补偿档差。曝光已截断的图像也无法靠增益恢复丢失内容。

## 接入机身与性能

先在电脑验证物理倍率、响应曲线及不同光照下的预测误差；这一步只有原型意义。机身交付仍需要确认取景处理入口、线程/缓冲所有权、原有ISP增益或LUT接口和可靠重打包/恢复方式。

若已有ISP显示增益或LUT接口可复用，优先让参数变化时更新映射，避免每帧新增复杂CPU处理。现阶段未找到并验证该接口，没有承诺帧率、CPU开销、噪点/景深/运动效果模拟或可刷机补丁。
