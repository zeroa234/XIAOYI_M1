# 单次 ISO 取景对照与恢复

本步骤接续已验证的电脑直连相机取景路线，针对用户要求的曝光亮度预览调查。用户补充当前高反差黑白滤镜；它可能改变灰度曲线与裁剪，所以先暂用标准色彩建立可比较基线，完成后恢复。

## 限定范围

脚本 `scripts/probe-exposure-preview.py --run` 仅执行一次原ISO→下一档固定ISO→原ISO的对照。例如若新取景仍报告100，则目标是200。原ISO必须由本次新元数据读取，不使用上一次采集值代替。必须是M档、已知固定ISO、可读快门/光圈与色彩模式；条件不符即结束，不发送测试设置。

如果原色彩不是Standard，临时切换到Standard；最终恢复原ISO和原色彩。所有设置都使用已审阅的上游枚举及JSON构造器，仅允许ISO/ColorMode，不能扩展到任意指令。不会改快门、光圈、焦距、白平衡或对焦模式，不拍照/录像/删文件/刷固件。

## 执行顺序

1. 启动取景，读取本次连续完整帧，写下原ISO、色彩、M档、快门和光圈。
2. 必要时暂用Standard，待新帧确认后保存基线。
3. 将ISO调高一档，待新帧报告目标ISO、Standard与固定的其他曝光参数后记录对照。
4. 无论中途回复丢失、设置被拒绝或取消，都尝试一次恢复原ISO（若已发过ISO意图）和原滤镜（若已发过色彩意图）。
5. HTTP回复与新取景元数据分别验证；仅HTTP200不称为恢复完成。元数据由完整2048字节参数头独立确认，不要求JPEG完整；等待设置前已开始到达的旧参数头不作为新确认。恢复阶段至少一份满足时间条件的新参数头，测试阶段使用多份参数头确认。未确认的恢复在结果中明确标记，并以失败状态退出。
6. 先请求结束遥控，再关闭UDP监听。无重复尝试或循环压力测试。

每个等待元数据窗口最多2秒，命令超时2秒；对照与恢复期间接收原始数据的上限为25秒，之后再给退出保留4秒排空时间。正常执行通常更短，不是持续取景工具。`probe-progress.json` 在每次设置前记录意图，超时仍按“可能已应用”处理。

## 条件与证据

测试需要用户固定相机、光线和场景，不在手机里同时操作。尚在等待该条件确认时，不开始真机设置。

数据写入新的 `output/live-captures/<UTC时间-iso-probe-标识>/`。取景图及原始包不提交Git。亮度分析只用独立核对哈希且完整的JPEG：没有标准色彩基线图就不调ISO，元数据不会冒充图像。分析复用Pillow，选取同一张基线里亮度16..220的固定像素掩码，比较各阶段JPEG亮度统计；不实施自写自动曝光算法。

本地现有上游解码器和另一公开项目都在整帧完成后提取参数，首轮测试遇到丢失JPEG分包导致漏掉状态确认。保留原图像解码器后，新增的 `src/liveview_metadata.py` 仅按已有12字节包头与2048字节参数区定义，有界缓存同一帧的连续前缀；支持乱序前缀、拒绝缺失/冲突片段，不生成任何缺失图像数据。这是本项目自写的参数确认适配，不是新的图像解码或相机曝光算法。

首轮实际只发送两次色彩设置，没有发送ISO设置。事后离线重放1788个原始包，得到50份完整参数头（仅6幅完整JPEG），确认ISO一直100且原黑白滤镜已恢复。原始自动判定未改写，另存 `reports/exposure-probe-first-attempt-postcheck.json` 说明采集器误判和恢复证据。

JPEG非线性色调、光照、画面/焦点变化、自动白平衡和高光裁剪仍可能影响结果。元数据ISO变化也不等于独立确认传感器实际增益。无自动“修好/坏了”的判定阈值，不用该对照推断CPU性能或故障根因。

## 已有离线验证

`tests/test-exposure-probe.py` 验证11项，覆盖原值恢复、回复丢失/取消、无效输入、缺失基线、旧参数头不作为新确认，以及固定掩码统计。`tests/test-liveview-metadata.py` 另有9项前缀格式/边界/乱序/缺失/冲突测试。均使用本地模拟状态，无相机通信。

原有回环采集测试另覆盖UDP监听/停止顺序、帧元数据通知及非本会话拒绝时不停止其他客户端。当前文档不宣称真机对照已完成。
